## XrSelect (4c00f34)

### Done
- New component `XrSelect` (#16): `v-model`, options as strings or
  `{ label, value, description, disabled }`, `placeholder`, `placement`
  (below / above), `maxHeight`, events `change` / `open` / `close`,
  exposed `open()` / `close()`. Docs page + live demo, README row,
  changeset, playground (List tab: artist filter over the tracks).
- `XrScene` gained a press hub (`PRESS_HUB`): any popup can now hear a
  press anywhere on vue-xr-ui UI or in empty space.

### How
- The list is an absolutely positioned XrPanel + XrList inside the select,
  hidden with `display: none` (keeps scroll, takes no pointer). It is drawn
  with `renderOrder: 1`, moved 8 mm towards the viewer, and gets
  `pointerEventsOrder: 1`, so a press on an option never reaches the track
  behind it.
- Press outside: listening on the scene would make every mesh a pointer
  target (pmndrs intersects objects whose ancestors have listeners). So the
  hub listens on every UI root (already targets) and on pointer-events'
  void object (what a ray hits when it hits nothing).
- Rejected: a dialog-style backdrop plane. It would block the press on the
  other control and gets clipped inside panels.

### Learned
- uikit `zIndex` subtracts majorIndex × 1 cm from the hit distance: with
  zIndex 10 a fingertip "pressed" 10 cm early and pokes broke. `zIndexOffset`
  only orders panels, and later text showed through. `renderOrder` works.
- Sphere pointers (hand grab and fingertip touch) report a pointerdown on
  the void whenever nothing is within reach: ignore those, but not sphere
  presses on real UI (the reviewer caught that the first filter ignored
  every poke outside).
- TestHook's `worldCenter` gives odd values for nested texts, and a poke
  aimed near an open list can land on an option: the poke-outside test
  pokes the active tab instead.
- Both gotchas went into CLAUDE.md.

  containers (XrSelect inside XrList)".

## The rest of the 0.2 components (ea0224b..7f7a562)

### Done
- New components: `XrIcon` (Lucide icon nodes or SVG strings; `XrButton`
  takes `icon` / `iconEnd`, round when icon-only) #20, `XrCheckbox`
  (`indeterminate`) and `XrRadioGroup` #18, `XrProgress` (bar,
  indeterminate bar, spinner) #19, `XrNumberInput` (− / + with
  hold-to-repeat, typed text clamped on Enter / blur) #17. Each has a docs
  page with a live demo, a README row, a changeset and e2e (mouse, ray,
  poke).
- `XrDialog` keeps text focus inside and stacks: fields behind cannot take
  focus, focus returns on close, a dialog over a dialog opens nearer, Escape
  closes only the topmost #53.
- `XrTooltip` bubble draws over neighbouring text #55. `XrSelect`'s list is
  a layout root of its own and is no longer clipped by an XrList #56.
- JSDoc on every public prop and event; the docs build fails without it #22.
- Playground: a Form tab (icons, checkboxes, radio, number input, a
  scrolling list of selects, progress) and stacked dialogs in the Type tab.

### How
- uikit's `Svg` only fills shapes and Lucide is all strokes, so XrIcon
  triangulates strokes with `SVGLoader.pointsToStroke`, merges them into one
  geometry (cached per SVG, ref-counted) and fits the viewBox in a uikit
  `Content`. The library depends on no icon package; it copies the three
  icons its own controls draw.
- Popups: `runtime/popup.ts` creates a separate uikit root next to the
  anchor's root and places it every frame at the anchor's corner
  (root placement × the anchor's `globalPanelMatrix`). Content still comes
  from the select's Vue tree through a portal that provides the popup root
  as `UIKIT_PARENT`. It closes when the anchor is hidden or clipped.
- Modal stack (`runtime/modal.ts`): open dialogs, each with the field to
  give focus back to; a dialog closed from under another hands that record
  up. XrTextField blurs itself if it gets focus outside the top dialog.
- Indeterminate progress moves by setting `transformTranslateX` straight on
  the node each frame: no Vue render, no relayout.
- The `reviewer` agent went over the whole range; its fixes are 7f7a562.

### Learned
- Timers fire late in the emulator (SwiftShader frames take 100-200 ms) and
  on a busy headset: hold-to-repeat must count from the clock, and several
  steps in one tick must start from the value just emitted (the parent has
  not passed it back yet).
- A popup that is a separate root breaks e2e that aimed by label: labels
  repeat (track rows say the artist names). Name parts (`option-<value>`,
  `<name>-popup`). Also the centre of a big container can lie under a popup.
- Escape listeners on `window`: a popup inside a dialog needs the capture
  phase plus `stopImmediatePropagation`.
- CI failures on the earlier pushes today were flakes from slow frames
  (Backspace hold, number input hold), both fixed.

## Milestone 0.4 Mixed reality (83b4e2d..HEAD)

### Done
- Passthrough (#33): `<XrScene>` clears to transparent and hides
  `scene.background` in `immersive-ar`, restores them after; `recenter`
  event; `<XrEnterButton mode="auto">`; the emulator takes IWER's furnished
  rooms. Playground: `?scene=mr` (the MR scene), linked from the overlay.
- `<XrFollow>` lazy follow and `<XrBillboard>` (#34).
- Planes and snapping (#35): `useXrPlanes()`, `<XrPlanes>`, `<XrWindow snap>`
  (flat on walls, standing on tables), `snap` / `place` events.
- Persistent anchors (#36): `useXrAnchor(id)`, `<XrAnchor>`,
  `<XrWindow anchor="name">`; persistent WebXR anchors with the floor-space
  pose in localStorage as a fallback.
- `<XrHandMenu>` (#37): a menu above the palm when it faces you.
- E2E (#38): `e2e/mr.spec.ts`, 13 tests in IWER's scanned living room:
  passthrough, head turns and recentre, billboard, ray and pinch snapping,
  anchors across reloads (and that the headset anchor wins over the
  stored pose), hand menu with a poke. 76 e2e tests in total.
- Mixed reality guide (#29), pages for the five new components, testing
  guide section, README, CLAUDE.md gotchas.

### How
- Everything world-space comes from `spaceToWorld` (pose in the reference
  space, then the scene origin): planes, anchors, hand joints.
- Follow and billboard are `TresGroup` wrappers moved in `useXrFrame`, so
  they work around any content, not only panels.
- Snapping projects the carried point into each matching plane's local
  space; walls take the plane's normal flipped toward the viewer, tables
  lift the window by half its height.
- Anchors: one shared registry per id so a window and a "forget" button on
  the same id stay in sync; one restore per handle and session.
- Reviewer agent: fixed leaked persistent handles (orphans deleted next
  session), a tap on the handle re-anchoring, stale planes after the last
  user, follow facing from last frame's position, the `auto` doc.

### Learned
- three.js keeps the XR camera at the left eye until render: everything
  that faced "the viewer" was 2 degrees off. Now the eye midpoint.
- three.js `setAnimationLoop` also restarts the window-rAF loop, so in the
  emulator (and desktop Chrome + PC VR) our loop runs twice per frame, once
  without an XRFrame. Dropping those ticks broke emulator pokes, so MR code
  ignores them instead; #61 tracks the real fix.
- In IWER, awaiting `store.requestFrame()` resumes after the frame is
  inactive (all callbacks share one task): create anchors inside the frame.
- IWER's recenter moves the user, not the origin: anchors vs pose cannot be
  told apart that way; the test spoils the stored pose instead.
- Furnished IWER rooms render at ~2 fps in software GL; scanned ones ~8.
- CI run 55 failed on the known page-reload flake (form.spec), not on MR.
