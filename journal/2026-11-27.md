# 2026-11-27

## Quest headset bugs (#62 #63 #64 #65 #66)

Aleksandr tested on the Quest 3 on 2026-11-25 and found five problems; all
five are fixed in code and wait for a headset check (`needs-headset`).

### Done
- **System keyboard (#62).** No caret, typing did nothing, the keyboard
  opened only once. XrTextField now focuses on the *release* of a press when
  the session has a system keyboard (inside the session's `select` event
  for a trigger or pinch, else on pointerup), and drops focus when the
  session comes back from `visible-blurred` (keyboard closed), so the next
  tap opens it again. The playground's Type tab shows a "Keyboard events"
  log in the headset so the next report says what Quest actually did.
- **Back of panels (#63).** Windows, dialogs and root panels draw their
  outer plate from both sides (`DoubleSidedPanelMaterial` in
  `ROOT_DEFAULTS`, and on the XrPanel directly inside an XrWindow/XrDialog
  via `SURFACE_HOST`). Inner panels, text and icons stay front-only.
- **Dialog dimming (#64).** The backdrop is now a BackSide sphere (5 m)
  around the head, no depth test, renderOrder / pointerEventsOrder 100
  (+10 per stacked dialog); the dialog root is one above. It dims the whole
  scene, follows the head, fades in over 150 ms. `RENDER_LAYER` lifts
  popups (XrSelect) and tooltips inside a dialog above it.
- **Blur (#65).** XrScene defaults `frameBufferScaling: 'high'` (device
  native) and `foveation: 0` (three.js defaults to 1). Docs: a Quest 3 has
  ~25 px/degree vs 60-100 on a monitor; that part is inherent.
- **Exit with hands (#66).** New `XrExitButton` (in-scene, only in a
  session) and `XrSessionMenu` (left palm pinch → "Leave VR?" Stay / Exit).
  Playground: exit button in the main window header and the MR HUD, a
  session menu in both scenes.

### How
- uikit's Input binds `this.focus` in its constructor, so the only way to
  intercept its press-to-focus is a subclass override (`FieldInput.gate`);
  our own calls go through `focusNow`. uikit merges our `onPointer*`
  property handlers with its own (ours first), so a press is tracked even
  though uikit stops propagation.
- uikit forces `material.side = FrontSide` after creating a panel material;
  the double-sided class pins `side` with a prototype accessor.
- The backdrop's hit test: pmndrs sorts by `pointerEventsOrder` before
  distance, so a far sphere still beats every UI panel except the dialog.
  Touch and grab pointers are denied on it: a sphere pointer is always
  "inside" its bounds and closed the dialog on every poke.
- `useXr().exit()` waits one task: ending the session inside pmndrs'
  pointer dispatch threw "reading 'object' / 'commit'".
- Palm detection moved from XrHandMenu into `runtime/palm.ts`, shared with
  XrSessionMenu. The session menu arms on `selectstart` (palm within 50° of
  the eyes, using the event's frame) and opens on `selectend`, with
  `closeOnBackdrop: false`, so the opening pinch cannot answer it.

- Self-review (reviewer agent) fixes: the field's padding captures the
  pointer and a `select` flushes a focus request only while that press is
  held (a stale request opened the keyboard on a later pinch elsewhere);
  stacked dialogs take one layer above the topmost open one (not the count);
  the dialog root has no depth test (it wins every ray, so nothing nearer
  may hide it); XrKeyboard rises above the top dialog while it types into a
  field inside it (the backdrop swallowed its rays; e2e added); `exit()` is
  once per session; popups provide a raised layer to their content;
  XrSessionMenu got `hint` / `exitLabel` / `stayLabel`, and in the MR
  scene its gesture is off while the left hand menu is open (same pose),
  with an Exit button in the hand menu instead.

### Learned
- Meta's docs: the system keyboard turns the session `visible-blurred`,
  delivers text only through the field's value and `input` events, starts
  each opening with an empty buffer, and blurs the field when it closes.
  Their sample focuses inside the `select` event.
- Meta's docs say a left palm pinch ends a WebXR session; on Aleksandr's
  Quest it did not. Never rely on a system gesture as the only exit.
- E2E: a render check works by `renderer.render` then `gl.readPixels` in
  the same task (TestHook `pixel`), no preserveDrawingBuffer needed.
